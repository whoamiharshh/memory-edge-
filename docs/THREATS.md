# Threat model: what is mitigated, what is left, and which test proves it

Prototype scope. We do **not** claim the system has no security bugs. Each row: threat → mitigation → residual risk
→ the test that exercises it. The design rationale is in [RESEARCH.md Part K](RESEARCH.md#part-k--security-threat-model).
"Test" means a pytest in `tests/` that ran green on the build laptop; "documented" means there is no automated check.

| Threat | Mitigation (built) | Residual risk | Proof |
|---|---|---|---|
| **Unauthorized sync** (no token, someone else's token) | Per-device bearer token, stored only as sha256; tenant, device and site come from the token record, **never from the payload** | Token theft (next row) | `tests/security/test_security.py::test_push_without_or_with_bad_token_is_401`, `::test_tenant_comes_from_token_and_tenants_are_isolated`, `::test_token_registry_stores_only_hashes` |
| **Credential theft / stolen device** | Tokens are revocable, **expire after 30 days** and are renewed automatically by the device (old token: 10-minute grace); with `--mtls` a stolen token alone is useless without the device's certificate, and a stolen certificate is **revoked** with `tools/make_certs.py revoke <device>` (CRL checked for every client, TLS >= 1.2); **technician notes are AES-256-GCM encrypted at rest** (also in the journal), key protected by Windows DPAPI | Other fields (fault class, actions, fingerprints) are not encrypted - use OS disk encryption (BitLocker / LUKS / FileVault); on non-Windows the key file is only owner-readable; a revoked certificate is refused on every NEW connection within ~2 s (the running cloud reloads the CRL), an already open keep-alive connection lasts until it closes (revoke the token too for an instant cut-off) | `::test_revoked_token_is_refused_on_next_request`, `tests/security/test_token_expiry.py`, `tests/security/test_notes_at_rest.py`, `tests/security/test_tls.py::test_mtls_refuses_a_revoked_device_certificate`, `::test_mtls_revocation_takes_effect_without_restart`, `::test_server_refuses_tls_below_1_2` |
| **Privilege escalation / a single rogue admin** | Roles `device` / `admin`; token issue, revoke and quarantine need admin; **retraction needs two different admins** (the first call only records a request); every admin action is written to a **hash-chained audit log** | Two colluding admins; a file-level attacker can rewrite the whole audit chain (keep a copy of its head hash) | `::test_device_role_cannot_use_admin_endpoints`, `tests/security/test_hardening.py::test_admin_actions_are_in_a_hash_chained_audit_log`, `test_security.py::test_retraction_is_a_tombstone_and_recomputes_tallies` (same admin refused) |
| **Tenant isolation** (read another tenant's fleet) | Separate Qdrant collections per tenant (`events_`, `cases_`, `mirror_`) + tenant from token; the snapshot endpoints only ever address the caller's own `mirror_<tenant>` | A bug in tenant routing would leak; covered by tests, not by proof | `::test_tenant_comes_from_token_and_tenants_are_isolated`, `tests/integration/test_mirror_snapshot.py::test_mirror_is_per_tenant` |
| **Replay / duplicate submission** | Deterministic `event_id` + `insert_only`; tallies are recomputed from stored events, so a replay cannot double-count | None known | `::test_replayed_batch_is_counted_once`; `bench/sync_partition.py`: 1,000 events, 139 lost acks → 0 duplicates |
| **Forged evidence for another device** | The cloud recomputes the event id from the *authenticated* device id; mismatch → rejected | — | `::test_device_cannot_forge_another_devices_event_id` |
| **Malicious / compromised device** (fake "worked" reports) | Counts per site are shown; one site cannot create "consensus"; contradictions are flagged DISPUTED; **plausibility checks** reject incomplete verification, future or impossible timestamps and a "worked" fix above its own vibration limit; **quarantine** pulls ALL evidence of a device in one reversible step and revokes its tokens; the admin view shows per-device **evidence counts** and whether its **code matches the release** (shared/integrity.py); follow-ups show when a reported fix did not hold | An insider with a valid token can still add plausible false evidence; the code check is tamper EVIDENCE (a fully compromised device can send the expected hash - real attestation needs secure boot / TPM) | `::test_one_site_cannot_manufacture_consensus`, `test_hardening.py::test_quarantine_pulls_all_evidence_of_one_device_and_is_reversible`, `::test_implausible_evidence_is_rejected`, `::test_code_integrity_status_per_device`, `tests/integration/test_weakness_fixes.py::test_a_device_cannot_report_follow_ups_for_another_devices_fix` |
| **Malicious payload** (NaN, Infinity, oversized, wrong enums, extra fields) | Pydantic schema, fixed vector dims, finite floats, enums, length caps, 512 kB body limit, 50 events per batch | Parser bugs in dependencies | `::test_infinity_and_nan_literals_rejected`, `::test_malicious_events_rejected_individually`, `::test_oversized_body_and_batch_are_refused`, `test_mirror_snapshot.py::test_partial_endpoint_validates_manifest` |
| **Sync flood (DoS)** | Per-token sliding-window rate limit (120 requests / 60 s) | A distributed flood from many tokens | `::test_rate_limit` |
| **Embedding inversion** (recover note text from vectors) | Text embeddings are **never shipped**; the cloud embeds the shared redacted text itself | The 27-d vibration fingerprint is shared; low-dimensional physics, but still machine-identifying metadata | `::test_outbound_event_has_no_raw_note_signal_or_text_embedding` |
| **Personal data in notes** | Notes stay local by default; shared only on opt-in **and** only if the redactor finds nothing: regex (email, phone, ids, URLs), denylist, **10,562 real given names** (Wikidata, CC0), unknown mid-sentence capitals, and a **name-likeness model** trained on real names vs real maintenance words | Measured on real logbook notes with names inserted (`bench/redaction.py`): names on the list 100 %; names NOT on the list 95 % in normal typing, 85-87 % in ALL CAPS / lower case (75 % on phrasings written after the rules); 0.8-2.6 % of clean notes wrongly kept local (the safe direction) | `tests/unit/test_shared.py`, `tests/unit/test_redact_names.py`; demo step 3 |
| **Prompt injection via notes** into the local LLM | The LLM has no tools, is outside every decision, and each output sentence must cite evidence and not advise; failures are dropped | A cited sentence can still paraphrase imperfectly; it is labelled AI-generated | `tests/ai/test_rag.py::test_brief_injection_echo_is_removed`, `::test_checker_drops_bad_sentences` |
| **XSS / clickjacking in the UIs** | All data rendered with `textContent`; no `innerHTML` anywhere; **Content-Security-Policy** (`script-src 'self'`, `frame-ancestors 'none'`), `nosniff`, `no-referrer`, `Cache-Control: no-store` on every API response; microphone/motion allowed only for the device's own origin | Inline `style` attributes are still allowed by the CSP | `::test_ui_never_uses_innerhtml`, `test_hardening.py::test_security_headers_on_both_apps`; `tests/ui_check.py` (0 console errors) |
| **Local API abuse** (another process on the device) | Every `/api` route needs the operator token (constant-time hash compare); binds to localhost; on a network address the launcher **refuses a short or demo-style operator token**; request bodies are size-limited | Anyone with the operator token has full local access | `::test_device_api_requires_operator_token_and_escapes_nothing_server_side`, `test_hardening.py::test_weak_operator_token_refused_on_a_network_address` |
| **Compromised server** poisons every mirror | Mirror is read-only, never overwrites local episodes; retractions are auditable; version-guarded mirror writes | Full server compromise remains critical | Out of scope; documented |
| **Stale or torn fleet mirror** | Full refresh restored beside the live mirror and swapped only after a probe; crash mid-swap repaired on boot; failed partial → full rebuild; a broken mirror never breaks local search | Between a failed partial apply and the rebuild, fleet results are unavailable (local memory still works) | `test_mirror_snapshot.py::test_corrupt_full_snapshot_leaves_old_mirror_in_use`, `::test_failed_partial_apply_triggers_full_rebuild`, `::test_crash_mid_swap_is_repaired_on_boot` |
| **Lost writes on crash** | Journal (SQLite) first, shard write + `flush()` second, replay on boot; K4 finding: Edge loses unflushed writes on hard kill | — | `tests/failure/test_store_durability.py` (hard kill, 0 acknowledged writes lost), `tests/integration/test_fleet_flow.py::test_journal_replay_after_crash_between_sqlite_and_shard` |
| **Concurrent edits** (two technicians, two tabs) | Every edit carries the version the screen showed; a stale edit gets 409 CONFLICT and writes nothing | Scripts that omit `expected_version` keep last-write-wins | `tests/integration/test_device_lifecycle.py::test_stale_edit_is_refused_and_writes_nothing`, `::test_api_reports_conflict_as_409` |
| **Silent network use by an "offline" device** | Offline-first design; models load from local files with `HF_HUB_OFFLINE=1` | — | `bench/offline_check.py`: 15/15 functions with a socket guard, **0 connection attempts** (guard self-test catches a deliberate request); `tests/failure/test_offline.py` |
| **Secrets in the repo** | `.gitignore` covers runtime state (live demo tokens), raw data, models, `.env`; demo operator tokens are fixed demo values, documented | Human error | `tests/security/test_no_secrets.py` (credential patterns in tracked files, live tokens not committed, private paths ignored) |
| **Insecure transport** | HTTPS with a private CA (`tools/make_certs.py`); devices verify the cloud certificate against `ca.pem`; cloud and device launchers **refuse plain HTTP on any non-localhost address** unless `--insecure-lan` is given | Localhost demo stays HTTP (traffic never leaves the machine); mTLS is optional (`--mtls`; with it the certificate name must equal the token's device id, so an admin needs a certificate named after the admin id, e.g. `make_certs.py device admin`); a phone that clicks through the certificate warning is encrypted but not verified; with `--mtls` the fleet UI needs a client certificate in the browser | `tests/security/test_tls.py` (trusted client connects, untrusted refused, plain HTTP to the TLS port fails, launchers refuse plain HTTP on 0.0.0.0, `::test_mtls_token_must_match_the_certificate`) |
| **Phone sensor page** abused to inject data | `/api/ingest/signal` needs the operator token; size, finiteness and shape checks; the page only works in a secure context | Anyone with the operator token can feed fake sensor data (same trust level as the technician) | `edge/api.py` validation; profile tests |
| **Wrong or tampered fix procedure** | Every procedure must cite a source (URL or "site SOP") or the library refuses to load; shown as reference with "follow the manufacturer's manual"; never generated by the LLM | A wrong site SOP is shown as written; review is a site process | `tests/unit/test_procedures.py` |
| **Wrong device clock** (drift, no NTP, a deliberate change) | Every push carries the device time; the cloud measures the offset and corrects that device's evidence timestamps (keeps the original); offsets are shown to the device and to admins; a push without a device time and a future date is refused | A device that lies about its clock AND its timestamps consistently shifts its own dates (dates are shown, never used to decide) | `tests/failure/test_network_faults.py::test_wrong_device_clock_is_corrected_not_rejected`, `::test_future_event_without_a_device_clock_is_still_refused`; `bench/network_faults.py` (worst corrected-time error 1.0 s) |
| **Bad networks** (latency, loss, lost acknowledgements, stalls, outages) | Outbox first, deterministic event ids, insert_only, per-event acks, retry with backoff + jitter, 30 s read timeout, follow-ups idempotent | Very long outages only delay sharing (evidence waits in the outbox) | `tests/failure/test_network_faults.py` (50 % cut link, stalls), `bench/network_faults.py` (6 scenarios, 0 lost / 0 double), `bench/sync_partition.py` |
| **Untrusted uploads** (manual PDFs, machine card, audio) | Operator token; manuals <= 20 MB, <= 400 pages, text only (pypdf, no scripts), refused when encrypted or unreadable; machine-card values range-checked; audio 0.5-5 s of 16-bit PCM | A crafted PDF could still hit a pypdf parser bug (same trust level as the operator) | `tests/unit/test_manuals.py::test_bad_manuals_are_refused`, `tests/unit/test_machine_card.py::test_invalid_cards_are_refused`, `tests/unit/test_acoustic.py::test_audio_route_refuses_bad_input` |
| **One stuck backend call freezes the fleet** | Per-thread Qdrant clients, **lock stripes** instead of one global lock, 20 s timeouts, coalesced case recompute (reads flush first), full mirror snapshot built once per version | Throughput is bounded by one laptop in the measurement | `bench/scale_fleet.py` (20 devices at once: 1,000 events, 0 lost, 0 double-counted, identical mirrors), `tests/integration/test_coalesced_recompute.py` |
| **Lost or tampered backups** | `tools/backup.py`: device archive with a SHA-256 manifest, restore refuses a damaged archive or a non-empty target and reopens the store to count points; cloud backup = Qdrant snapshots of every tenant collection | Backups must be stored off the machine by the operator; notes in a Windows backup decrypt only on the same account | `tests/failure/test_backup_restore.py` |
| **Supply chain** | Exact versions pinned in `requirements.txt`; `qdrant-edge-py` pinned (beta) | `pip-audit` of the installed environment (63 packages, 28 Sep 2026): **1 advisory, `diskcache` 5.6.3 PYSEC-2026-2447** (pickle deserialisation of its cache files; no fixed release). It is pulled in by llama-cpp-python; **our code never creates a disk cache**, so the exposure needs an attacker who can already write to a cache directory we do not use. No hashes in the lockfile yet. | `uvx pip-audit --path .venv\Lib\site-packages` |

## Online retrieval: a deliberate hole in "nothing leaves the device"

Ask can search the web (`edge/online.py`). This is the only part of the device that reaches the network for
a reason other than syncing with its own cloud, so it is stated here rather than buried.

| | |
|---|---|
| **What leaves** | The question text, and nothing else. No episode, note, fingerprint, embedding, device id, site id or machine id is in the request. |
| **Who sees it** | The configured search provider, and anyone able to observe that connection. DuckDuckGo and Wikipedia are the keyless default; Brave and Tavily are available with a key. |
| **What cannot leave** | A question about this machine's own record is answered from stored state and is never sent, in any mode (`test_a_question_about_this_device_never_leaves_it`). |
| **Off switch** | Settings -> Ask -> "This device only", or `EDGE_SEARCH_PROVIDER=none`. Also off whenever the device is offline. |
| **Residual risk** | A technician can type machine-identifying detail into a question, and it will be sent. The setting is the mitigation; the product does not try to redact free-text questions, because a redactor that silently rewrote a question would make the answer untrustworthy in a different way. |
| **Honesty** | Every answer reports whether it came from the device, the internet, or both, and web evidence is shown with its URL so it can be checked. |

Tests: `tests/unit/test_online.py` (routing, both off switches, the device-only rule, provider failure).

## Not built (stated, not hidden)
- Hardware-rooted device identity (secure boot / TPM attestation); the code-integrity hash is tamper evidence only.
- Encryption of structured fields and vectors inside the device shard (they must stay searchable): rely on OS disk
  encryption for a stolen device.
- A per-device trust score (deliberately cut: counts are shown instead, RESEARCH.md).
- The Laya experiment was run in an isolated environment and is **not** part of the device; its environment and model
  were deleted after the measurement (28 Sep 2026); see `docs/BENCHMARKS.md` §17.
